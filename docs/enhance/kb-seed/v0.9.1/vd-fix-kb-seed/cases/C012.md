# C012 GCC 专有编译选项被 Clang 拒绝

- **包**：（见来源）
- **告警标志**：[[unknown-argument]]
- **根因类别**：工具链选项
- **是否真 bug**：非 bug

## 报错原文

典型形式（Clang 的诊断格式，不是本库某次日志的原文；补到真实日志后替换）：

```
clang: error: unknown argument: '-fvar-tracking-assignments'
```

这是错误级诊断，不带 `[-W…]`，不能用 -Wno-… 关掉。

## 解决方案

- **类型**：通用做法（以往记录摘要；具体 CL 待补）。
- 先查选项从哪来：
  - 来自 rpm 宏：**先定位这个宏的有效定义从哪来**（rpm 宏可以定义在 build.conf / project_config、base 包安装的宏文件、或本包 spec 里，后定义的会覆盖先定义的）。查法：在该包的 gbs build root 里只读执行 `rpm --eval '%{宏名}'` 或 `rpm --showrc`（不要在构建机宿主上执行，宿主看到的是 Ubuntu 自己的 rpm 宏）；构建日志里只有宏展开之后的选项，宏的出处要对照 build.conf、base 包的宏文件和本包 spec 来查：
    - 确实来自 build.conf / project_config：**不由本线改**（HLD §7.5 把修改 build.conf 列为违规），交给工具链负责人处理，案例里记处置；
    - 来自 base 包安装的宏文件（例如 LLVM / GCC 相关的 base 包）：按 R05 / R12 判断归属，在对应的包里提出修复；
    - 来自本包 spec：按本包规则处理（R08 写法）；
    - 没定位到来源之前，不把"来自 rpm 宏"直接当成 build.conf 的问题。
  - 来自包自己的 Makefile：在 spec 里按编译器条件处理（R08 写法）。

## 备选与为什么没用

`-Wno-unknown-warning-option` 等对"未知参数"无效；它是错误级诊断，不能用 -W 关掉。

## 需联动看的模块

- **头文件 / 接口 / 输入的提供者**：选项的来源：rpm 宏（有效定义可能在 build.conf / project_config、base 包的宏文件或本包 spec，先定位再定归属）或包自己的 Makefile
- **下游（依赖这个包、改了会受影响的）**：来自 build.conf 或 base 包宏文件时：所有用这个宏的包
