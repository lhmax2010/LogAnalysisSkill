# C008 未使用的私有成员：加 unused 属性还是删掉

- **包**：united-service（另有同类验收样本，见 packages/ 下的包页）
- **告警标志**：[[Wunused-private-field]]
- **根因类别**：未用代码
- **是否真 bug**：非 bug

## 报错原文

典型形式（Clang 的诊断格式，不是本库某次日志的原文；补到真实日志后替换）：

```
<文件>:<行>: error: private field '<成员名>' is not used [-Werror,-Wunused-private-field]
```

## 解决方案

- **类型**：通用做法（以往记录摘要；具体 CL、文件和修改前后摘要待补）。
- **先看成员所在的头文件会不会被安装**：头文件随 devel 包安装给其它包使用时，不删也不注释——会改变类的内存布局，属于 ABI 变化——改为加属性。
- 只在包内使用的类：按规则 R10，确实无用的成员不直接删，先注释掉并写明原因，真正删除由开发者决定。
- 加属性的写法：C++17 及以上用 `[[maybe_unused]]`；C++17 以下用 `__attribute__((unused))`——低于 C++17 时 `[[maybe_unused]]` 会再报一个"C++17 扩展"告警，在 -Werror 下同样是错误。

## 备选与为什么没用

只对 Clang 加 `-Wno-unused-private-field`：最省事，但会让所有同类问题都被压掉。

## 需联动看的模块

- **头文件 / 接口 / 输入的提供者**：—
- **下游（依赖这个包、改了会受影响的）**：成员所在头文件若随 devel 包安装，依赖这个包的下游会受布局变化影响——待依赖图（§7.8）确认有没有下游
- **同一根因的其它包或案例**：united-service
