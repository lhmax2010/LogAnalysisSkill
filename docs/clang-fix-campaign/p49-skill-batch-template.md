# P4.9 skill 批次设计模板

> 架构裁决以各批 FROZEN 稿为准,本文件仅承载跨批次规则。

## §A 开工前

1. **跨批次检查**(step-0 ⑰):grep 全部既有 FROZEN 稿中
   `owner=本 skill` 的符号,并逐项接收具名 DEFERRED;不得只查当前模块。
2. **三形态闭包**(step-0 ⑰):迁移边界须分别拉取调用闭包、类型字段闭包与
   数据来源闭包;闭包内跨层依赖须在设计期显式归属。
3. **判据 dry-run**(skill-1 v1.3):在规划终态 SPECS 与真实消费方上分两趟
   执行判据;第一趟保留 raw 命中,第二趟逐项核销 twin。twin 证据内联留痕,
   SUMMARY 必须与逐行终判一致。

## §B 设计稿必答

1. **权威归属表**(skill-2 v1.3,skill-5 v1.3.1):逐符号表使用
   `symbol | definition | owner` 三列;所有 skill 批次冻结前必须以 parser-only
   验证表可解析且行数/键集合与规划 inventory 一致,否则不得冻结。整体迁移模块
   仅在具备封闭 module-scope 判据时使用文件级归属。
2. **三概念口径**(skill-3 v1.3.1):分别陈述实测消费面、包根公开面与包根
   不导出面;每个数量只在定义节出现一次。
3. **迁移模式判定**(skill-4 §1.4):逐文件选择模式一(逐字节)、模式二(具名
   白名单)或模式三(双角色拆分)。双角色文件必须同时通过四项验收:定义区段
   AST 源文本逐字节一致、shared import 集合等价、零 `as X` 同名别名、包根
   不导出 shared 集合。
4. **twin 独立保留**(skill-2 §1.2):同名符号须按 `(definition, symbol)`
   审计;未有共同权威裁决时严禁因名字或字节相同而合并。
5. **arch 维度**(campaign 方法⑧):真实存在 arch 维度时必须有矩阵;不存在时
   以精确 grep 结果申请有据豁免,不得默认省略。
6. **公开契约**(skill-3 §2.3):SKILL.md 至少冻结 Inputs、Outputs、Errors、
   Side effects、Idempotency 五节,并明确包根公开与不导出集合。
7. **分支表准入**(skill-5 §4):每一行必须带真实代码锚;无锚即无证伪。
8. **分支清单准入**(skill-6 §11):用精确 AST selector 生成稳定 branch ID;
   未列 AST 类型 fail-closed,跨模块结果用 `EXTERNAL_BRANCH` 绑定本地调用点、
   外部模块行号与预期异常/返回。分支表引用须为 ID 全集子集,未引用 ID 逐项
   登记理由。

## §C 门禁与审计

1. **三入口同步**(skill-2 §4):新增顶级包须同步 pyproject package/mypy 路径、
   CI mypy 命令和 README PYTHONPATH;精确计数命令先在既有 skill 上自检。
2. **机械同步清单/执行期澄清②**(skill-4 §2.4,skill-6 commit A):definition、declared consumer、source root、
   package owner、surface guard、bridge 路径等必须逐项穷举,不得写“等”。凡对
   被抽取模块实现做 AST/源码枚举的门禁,其扫描路径须与 declared consumer、
   bridge 路径常量并列登记,并在实现迁移的同一 commit 同步,不得顺延到门禁
   汇总 commit(skill-6 commit A)。
3. **完整性护栏**(step-0 修订-6/7):实体模块的顶层符号与 SPECS 必须集合
   等价;别名识别须以 `MixedCaseAlias` 负 fixture 证明。
4. **A0 继承**(skill-4 A0,skill-5 参数化):复用
   `design_drift_ledger.py`,语料、版本序列、冻结目标、准入快照与必抓 binding
   由本批独立数据文件提供,不得覆盖前批数据。参数化后须复跑前批主门禁、
   admission、每条 per-binding 与每条 OUT_OF_SCOPE 负向证伪。
5. **binding 准入**(skill-5 A0):每个规划 binding 在冻结前必须确认引用侧
   存在承重条目;定义节写得完整而引用侧无锚时不得登记。无引用即无 binding,
   与“无锚即无证伪”同族。

## §D 冻结前四项必检

1. **附录对账**(skill-3 冻结):附录中的“零变更/唯一变更”逐句对照正文。
2. **计数对账**(skill-4):数量只在定义节出现一次,其余位置引用节号;ledger
   中扫描结果、期望值、负 fixture 数分别按各自数据源判定,不得互相反推。
3. **契约与用例双向闭合**(skill-3 §5.1):每条契约有用例,每个用例有契约。
4. **双门禁**(skill-4 §5.4/§5.5):反向漂移、正向 binding 与 admission
   证伪全部实跑;每个登记项还须有自身构造式负控制。
5. **准入快照对齐**(skill-5 A0):admission 的 required 集合必须逐项实测
   存在于所选快照;只存在于其它版本的缺陷归反向 ledger,不得混入准入清单。
6. **重写反向清点**(skill-6 §10):结构化重写前须证明旧版要点集为新版行集
   子集;要点集优先由脚本从实质 diff 自动提取,人工只允许删去机械可证的噪声。
7. **数值声明同轮生成**(skill-6 §11):声明数值类检查的首版值必须由脚本实跑
   产出,并与首次实跑同轮完成;不得先手填期望值再让脚本追认。

## §E 实现纪律

1. **先验可满足性**(skill-4):冻结后的第一个实现动作必须用真实输入验证规格
   可满足;发现冲突立即停止,不得编码绕过。
2. **pre-shim 证据时点**(skill-3/4):行为 parity 必须在旧实现仍独立、shim
   尚未合流前采集;post-shim identity 只证明接线。
3. **两阶段验证**(skill-2):抽取阶段的临时 PYTHONPATH/MYPYPATH 与安装后的
   `env -u PYTHONPATH -u MYPYPATH` 门禁分列取证,不可互代。
4. **测试所有权**(skill-2 §5.1):skill 行为、编排集成、legacy wiring 分节;
   行为测试随权威实现迁移,旧址 identity 不冒充行为证据。
5. **DEFERRED 纪律**(step-0 ⑯):每项延期须具名关门批次与延期对价;终止批次
   未关闭即阻塞总收口,不得继续转交下一批。
6. **冻结前置的时序表述/执行期澄清①**(skill-6 A0):“X 为冻结前置”表示
   X 的实跑必须先于冻结;X 的落盘 commit 可以后于冻结。冻结 commit message
   必须锚定实跑结果与脚本 SHA,后续落盘脚本须与该 SHA 一致;若中间修改脚本,
   必须重跑再冻结。设计稿须把实跑时点与提交顺序分开写明,避免与“首个 commit
   为冻结落章”的惯例冲突。`bdb5a55`/`3dc0466` 的脚本 SHA 一致性是首个实例。

## §F 方法论索引

- **⑩ 机械归属**(step-0):以真实 import、调用与类型图核验归属。
- **⑪ 正反双证**(P4.5):每条安全门同时具备正向与破坏性反向证据。
- **⑫ 正文即契约**(step-0):裁决回写正文,清单显式穷举且双向对账。
- **⑬ 外部完整性锚**(step-0):产物不自记哈希,由 Git commit 锚定。
- **⑭ 护栏实测**(step-0):配置存在不等于生效,必须记录工具 exit code。
- **⑮ 判据分类防滥用**(step-0):每个新符号类别配结构断言与负 fixture。
- **⑯ 过渡态转正**(step-0):延期是有截止点的状态,不是永久豁免。
- **⑰ 闭包迁移**(step-0):跨边界按调用、类型字段、数据来源三形态拉闭包。
- **⑱ 准入证伪**(skill-4):门禁及每个登记项在已知坏输入上必须转红。
- **⑲ 外部锚复核**(skill-4):被检对象、证据与 commit 三者分层锚定。
