# Decisions for BW-M4: E2E + Cline integration

| ID | Date | Decision | Source | Rationale | Impact |
| --- | --- | --- | --- | --- | --- |
| d001 | 2026-05-20 | BW-M4 owns real A/B/C/D workflow validation and unknown fallback validation. | BW-M3 review; `docs/build_workflow/DESIGN.md` §7. | BW-M3 intentionally limited validation to unit-level routing; v0.1 acceptance requires workflow-level proof. | BW-M4 dev_memory records real ffmpeg workflow results and E2E tests. |
| d002 | 2026-05-20 | Workflow prefers GBS's structured `/logs/fail/.../log.txt` when the wrapper log points to one. | BW-M4 real D validation. | The outer `compiler.log` can include a final `<gbs>some packages failed` wrapper error after the real RPM phase failure, causing analyzer Top-1 to become `raw_error`. The structured failure log preserves the package build context and ranks `%install` correctly. | `run_workflow()` still stores `compiler.log`, but passes the structured log to analyzer when it exists; otherwise it falls back to `compiler.log`. |
| d003 | 2026-05-20 | `CompileErrorSuggester` reads semantic class from `root_cause_candidates[0]` before falling back to `primary_error`. | BW-M4 review; observed M8 analyzer packets. | Analyzer packets do not put `semantic_class` on `primary_error` for compiler diagnostics; the ranked candidate carries it. | Compile advisory text now reports the real semantic class instead of `unknown`. |
| d004 | 2026-05-20 | Cline build workflow integration remains an example contract only. | `docs/build_workflow/DESIGN.md` §5. | The repository cannot validate a live Cline runtime, and workflow must not auto-apply patches. | `integrations/cline/build_workflow.json` documents invocation and post-processing without deployment assumptions. |
