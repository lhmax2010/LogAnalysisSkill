# Decisions for BW-M1: gbs_build_skill

| ID | Date | Decision | Source | Rationale | Impact |
| --- | --- | --- | --- | --- | --- |
| d001 | 2026-05-20 | Keep BW-M1 production code limited to `gbs_build_skill/`. | User BW-M1 instruction; `docs/build_workflow/DESIGN.md` §3. | BW-M1 should introduce only the standalone build runner and avoid coupling to analyzer/workflow concerns. | Implementation stays in the new package; only tests/dev_memory and minimal package discovery are outside it. |
| d002 | 2026-05-20 | CLI arguments mirror the v0.1 design: `--conf`, `--arch`, `--include-all`, `--output-log`, and `--timeout`. | `docs/build_workflow/DESIGN.md` §3.2. | The build skill should stay predictable and avoid workflow/analyzer concerns such as `--src-root` or suggestion options. | `python -m gbs_build_skill` is build-only; BW-M2 can wrap it without extra parsing ambiguity. |
| d003 | 2026-05-20 | stdout and stderr are merged and streamed directly into the log file while gbs runs. | User BW-M1 engineering detail; `docs/build_workflow/DESIGN.md` §3.1. | Streaming prevents losing the entire buildlog if a long build crashes or is interrupted, and merging preserves the user's `2>&1` expectation. | The runner uses `subprocess.Popen(..., stderr=STDOUT)` plus a reader thread that flushes each chunk. |
| d004 | 2026-05-20 | Timeout defaults to 1800 seconds and returns exit code `124` when triggered. | `docs/build_workflow/DESIGN.md` §3.2 and §9 risk table. | 30 minutes matches the design and GNU timeout convention; workflow callers can treat timeout distinctly from normal gbs failure. | Timeout kills the gbs process, writes a timeout marker to the log, and returns `124`. |
| d005 | 2026-05-20 | `gbs_build_skill*` is included in package discovery. | BW-M1 unit test import failure under `.venv/bin/pytest`. | Console-script pytest imports installed editable packages, unlike `python -m pytest` which includes the current directory. The new product must be installable from the monorepo. | `pyproject.toml` includes `gbs_build_skill*`; no analyzer code or analyzer package behavior changed. |
