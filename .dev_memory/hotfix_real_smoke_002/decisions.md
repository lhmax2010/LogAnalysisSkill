| d005 | 2026-05-19 | Needs-LLM prompt should be a compact fixed instruction that references packet fields, not a pretty-printed duplicate of all evidence. | A PR1 validation plus v0.5 token budget table: prompt template target is about 400 tokens. | Pretty-printing candidates/evidence doubled token cost and forced final truncation even when packet evidence itself could fit. | `_render_prompt` now includes primary error, top candidate, and evidence paths; detailed evidence remains in `packet.evidence`. |
| d006 | 2026-05-19 | `full_match` near-match recording must not alter existing direct-answer verdict gates. | M8 E2E zero-regression gate. | Using candidate confidence directly for all tier2 verdicts regressed existing fixtures. PR1's purpose is transparency, not Fix 5 confidence semantics. | Direct verdicts continue to use existing pattern confidence gates; near-match metadata records candidate confidence/failure reason for `needs_llm`. |
| d007 | 2026-05-19 | Near-match regex can ignore strict context gates, but only after event kind, negative patterns, and regex match. | A real linker command is associated with `make -j40`, so strict `tool_in` blocks the linker pattern while the message regex still matches. | Downstream LLM consumers need to see semantically applicable patterns even when context gates prevent direct answer. | A now records `linker_undefined_reference_tier2` with `failure_reason=confidence_below_tier2_threshold`; PR3 will address linker confidence semantics. |
| d008 | 2026-05-19 | Near-match entries expose both `id` and `pattern_id`. | PR1 review. | Some consumers read `matched_patterns[*].id`; returning only `pattern_id` made that field appear as `None`. | PR2 first commit adds `id` while preserving `pattern_id` for backward compatibility. |
| d009 | 2026-05-19 | Real hunk-ignored patch failures are canonicalized to the existing `Hunk #N FAILED` wording. | C real buildlog line `1 out of 1 hunk ignored`; PR2 scope excludes pattern-library changes. | The existing tier1 `patch_failed_hunk` pattern is already reviewed and conservative; canonicalizing scanner output lets quick_filter hit without changing `patterns/gbs_errors.yaml`. | C now fast-paths as patch tier1; original wording remains inside the canonical message after the prefix. |
| d010 | 2026-05-19 | `%prep` rpm-phase failures following a patch event are cascade children of the latest `%prep` patch event. | C real buildlog: patch failure lines immediately precede `Bad exit status ... (%prep)`. | The rpm-phase event is terminal noise derived from the failed patch command, not the root cause. | Ranker and packet assembly see the patch event as the root and the rpm-phase as non-terminal child. |
| d011 | 2026-05-19 | Patch failures in `failed_phase` receive a narrow `+0.10` rank boost. | Hotfix_002 Fix 4 design. | If quick_filter is bypassed in future flows, ranker should still prefer a failed-phase patch root over derived rpm-phase or generic events. | Adds `patch_failed_phase` confidence reason; no impact on non-patch classes. |
