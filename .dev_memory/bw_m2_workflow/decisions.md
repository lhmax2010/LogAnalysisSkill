# Decisions for BW-M2: workflow + DepsolveSuggester

| ID | Date | Decision | Source | Rationale | Impact |
| --- | --- | --- | --- | --- | --- |
| d001 | 2026-05-20 | BW-M2 registers only `DepsolveSuggester`. | User BW-M2 instruction; `docs/build_workflow/DESIGN.md` §6. | The revised design has seven Suggester classes overall, but six belong to BW-M3. | Registry starts small and must not silently include advisory Suggesters. |
| d002 | 2026-05-20 | Workflow calls `gbs_analyzer` through the CLI subprocess boundary. | `docs/build_workflow/DESIGN.md` §4.1; user BW-M2 instruction. | Analyzer is already an independent product with a stable runtime entrypoint and output schema; importing it would couple workflow to analyzer internals. | `gbs_workflow.workflow` invokes `python -m gbs_analyzer analyze ...` and consumes `analyzer_output/evidence_packet.json`. |
| d003 | 2026-05-20 | Workflow calls `gbs_build_skill` by Python import. | `docs/build_workflow/DESIGN.md` §4.1; BW-M1 runner contract. | `gbs_build_skill` is a same-repo build-only helper with a typed `BuildOptions`/`BuildResult` contract; direct import avoids subprocess parsing and keeps logs/exit codes explicit. | `run_workflow()` depends on `gbs_build_skill.runner.run_gbs_build` but does not change BW-M1 code. |
| d004 | 2026-05-20 | `DepsolveSuggester.matches()` checks only `packet.primary_error.kind == "depsolve"`. | User BW-M2 clarification. | Fast-path/tier decisions belong to analyzer; workflow should not duplicate verdict logic and should still suggest on future composite depsolve packets. | Depsolve suggestions remain available whenever analyzer identifies the primary error kind as depsolve. |
| d005 | 2026-05-20 | Depsolve suggestions emit git-diff patches plus markdown guidance, never applying changes. | `docs/build_workflow/DESIGN.md` §4.4 and §7. | The workflow must remain advisory; `git apply --check` is the validation boundary for generated patch syntax. | Suggestions are written under `.gbs_workflow/suggestions/` as `{NNN}_{suggester}_{slug}.patch` and `.md`. |
| d006 | 2026-05-20 | Build success short-circuits analyzer and suggester execution. | `docs/build_workflow/DESIGN.md` §4.1 step 2. | A successful build has no failure packet to analyze and should not spend time or produce speculative suggestions. | Workflow writes `workflow_summary.md` with status success and returns exit 0 without creating analyzer output. |
| d007 | 2026-05-20 | `gbs_workflow*` is added to package discovery and mypy package checks. | BW-M1 d005 package discovery precedent. | The new product must be runnable by `python -m gbs_workflow` from the editable install and checked in CI alongside the other packages. | `pyproject.toml` includes `gbs_workflow*`; analyzer and build-skill package behavior is otherwise unchanged. |
